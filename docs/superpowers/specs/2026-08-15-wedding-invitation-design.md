# 모바일 청첩장 — 디자인 스펙

## 목표

김현기 · 김다솜 결혼식(2026. 12. 13. (일) 오후 6시, 삼성금융연수원)을 위한 모바일 청첩장 웹페이지를 만든다. GitHub Pages로 배포하는 정적 사이트. RSVP(참석여부 체크)는 넣지 않는다.

## 디자인 톤

무드보드 브레인스토밍(`design/moodboard.html`)에서 5개 방향(A 그리너리, B 윈터, C 미니멀, D 파스텔, E 필름)을 비교했고, B 계열 중 **B-3 "에버그린 나이트"**를 최종 채택했다. 짙은 상록수 숲 + 저녁 예식 분위기.

### 팔레트

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-bg-top` | `#132318` | 배경 그라디언트 상단 |
| `--color-bg-bottom` | `#0B1710` | 배경 그라디언트 하단 |
| `--color-ink` | `#EDE9DD` | 본문 텍스트 (아이보리) |
| `--color-ink-bright` | `#FFFFFF` | 강조 텍스트 (이름 등) |
| `--color-muted` | `#B7C7B9` | 보조 텍스트, 메타 정보 |
| `--color-accent` | `#C79A6B` | 포인트 컬러 (구릿빛 앰버) — 룰선, 아이콘, 버튼 |

### 타이포그래피

- 디스플레이(제목류): `'Nanum Myeongjo', 'Noto Serif KR', serif` — Google Fonts에서 로드
- 본문/UI: 시스템 산세리프 스택 `-apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`
- 라벨/eyebrow: 자간을 넓힌(`letter-spacing: 0.3em` 내외) 대문자 소형 텍스트

### 톤앤매너 원칙

- 사이트는 하나의 고정된 비주얼(다크 에버그린)로 통일한다. 시스템 라이트/다크 모드에 따라 배색을 바꾸지 않는다 — 청첩장은 브랜드 정체성이 고정된 인쇄물에 가까운 성격이라 일관된 한 가지 톤이 맞다.
- 눈 내리는 연출(느린 속도의 falling snow)을 배경 장식으로 쓴다. `prefers-reduced-motion: reduce`에서는 애니메이션을 끈다.
- 흔한 "AI가 만든 것 같은" 톤(크림+세리프+테라코타, 보라-파랑 그라디언트, 이모지 섹션 마커, 카드에 둥근 액센트 바)을 피한다.

## 정보구조 (섹션 순서)

1. **커버** — 전체화면 인트로. 신랑·신부 이름, 날짜, 배경(사진 또는 영상 1개), 스크롤 유도 화살표
2. **초대의 글** — 초대문구, 신랑측/신부측 표기
3. **캘린더 & D-Day** — 12월 캘린더에서 13일 강조 + D-Day 카운트다운(오늘 날짜 기준 남은 일수)
4. **갤러리** — 사진 15장, 반응형 그리드 + 라이트박스(클릭 시 확대)
5. **영상** — 영상 3개, 세로로 순서대로 배치 (웨딩필름 / 프로포즈 / 비하인드 성격으로 구분)
6. **오시는 길** — 지도, 주소, 대중교통·주차 안내
7. **안내사항** — 식사·주차·화환·드레스코드 등 공지, 아코디언(접기/펼치기)
8. **마음 전하실 곳** — 계좌번호. 기본은 접혀 있고 버튼을 눌러야 펼쳐짐. 계좌별 복사 버튼
9. **마무리** — 감사 인사, 카카오톡 공유하기 버튼(스타일만, 실제 SDK 연동은 범위 밖)

## 샘플 콘텐츠 범위 (이번 구현)

- **사진 15장**: 실제 사진 파일이 아직 없으므로, 팔레트 톤의 CSS 생성 플레이스홀더 타일(번호가 매겨진 그라디언트 카드)로 채운다. 나중에 실제 이미지 파일로 교체할 수 있도록 갤러리 구조(그리드 + 라이트박스)는 실제 `<img>` 태그를 쓰는 것과 동일하게 짠다.
- **영상 3개**: 실제 영상 파일 없이, 재생 아이콘이 있는 플레이스홀더 카드(포스터 톤 + 라벨)로 채운다. 클릭하면 "샘플 영상입니다" 정도의 안내만 표시한다.
- **지도**: 실제 카카오맵/네이버지도 API 키가 없으므로, 스타일링된 지도 플레이스홀더(주소 텍스트 + 정적 배경)로 채운다.
- **계좌번호**: 실제 계좌번호 없이 형식만 맞춘 샘플 라벨("신랑 김현기 000-0000-0000 000은행" 형태의 예시 텍스트)로 채운다.

## 기술 방식

- **빌드 스텝 없는 순수 HTML/CSS/JS.** Vite 등 번들러를 쓰지 않는다 — 정적 페이지 한 장이라 번들러가 주는 이득보다 GitHub Actions 빌드 파이프라인을 추가로 관리하는 비용이 크다.
- 스크립트는 클래식 `<script>` 태그(ES 모듈 아님)로 작성해 `file://`로 직접 열어도 동작하게 한다.
- 로직이 있는 순수 함수(D-Day 계산 등)는 별도 파일로 분리해서 브라우저에서 여는 정적 테스트 HTML로 검증한다 (Node.js가 로컬에 설치되어 있지 않아 npm 기반 테스트 러너를 쓸 수 없음).

## 파일 구조

```
index.html
css/
  tokens.css       — 디자인 토큰(색상, 타이포 변수)
  style.css        — 레이아웃/섹션 스타일
js/
  dday.js          — 순수 함수: daysUntil(targetISODate, fromDate)
  main.js          — DOM 바인딩: 눈 효과, D-Day 렌더링, 갤러리 라이트박스, 아코디언, 계좌 토글, 복사 버튼
tests/
  dday.test.html   — daysUntil() 브라우저 테스트
README.md
.gitignore
```

## 배포

GitHub 리포지토리에 push 후 GitHub Pages(Settings → Pages → branch: main, root)로 서빙한다. 실제 push와 리포지토리 생성은 사용자 확인을 받은 뒤 진행한다.

## 범위 밖 (Out of scope)

- RSVP(참석여부 체크) 기능
- 실제 사진/영상 파일, 실제 지도 API 연동, 실제 계좌번호
- 카카오톡 공유 SDK 실제 연동 (버튼 스타일만 구현)
- 다국어(영문) 버전
